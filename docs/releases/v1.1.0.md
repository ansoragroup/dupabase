# Dupabase v1.1.0

Extends the v1.0.0 security release with tested PostgreSQL major-version and
Supabase SDK compatibility, while preserving existing public routes, project
keys, password hashes, encrypted credentials and response contracts.

- PostgreSQL 14–18 full-container tests, using a matching patched 16/17/18
  dump/restore client. Client 16 supports servers 14–15.
- Supabase JS 1.35.7 legacy contracts, previous 2.95.3 and current locked 2.117.2.
- Real S3 backup/restore and all ten forward PostgreSQL archive upgrade pairs,
  including auth, custom types, generated columns, functions and RLS.
- Dump compatibility checks before cleaning data; newer-to-older downgrade
  rejection preserves existing data. Custom restore uses one transaction.
- Atomic migration batches and concurrent-startup protection, with failure
  rollback tests and a v1.0.0 → candidate → v1.0.0 application round trip.
- Same-host performance comparison against v1.0.0, with raw trial results.
- Dashboard tooling upgrades to TypeScript 6, Vitest 5, jsdom 30, jest-dom 7,
  shadcn 4 and lucide-react 1; lint, type checks, 24 UI tests and production build.
- Docker-image dependency PRs, exact-image scanning before production
  publication, daily published-image scans and sequential deployment.

Keep `DATABASE_URL`, `PLATFORM_JWT_SECRET` and the existing
`BACKUP_ENCRYPTION_KEY`/credential encryption setup when updating the image.
There is no destructive schema migration in this release. A PostgreSQL server
major upgrade remains a separately verified database operation.

Use the immutable GHCR version tag or the attached image digest. Artifacts include
`compatibility-report.json`, `image-security.json`, `sbom.cdx.json`,
`image-digest.txt` and `SHA256SUMS`.

See [compatibility and upgrade policy](https://github.com/ansoragroup/dupabase/blob/v1.1.0/docs/compatibility.md) for precise coverage,
performance budgets and feature boundaries. OAuth/SSO, Realtime, Storage and Edge
Functions remain outside the implemented API. Upstream preview majors are not
promoted automatically; unsupported tool major proposals stay separate until
their dependency peer ranges and regression checks pass.
